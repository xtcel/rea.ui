## Context

引用画布元素时，选中的节点被写成一条 `AgentRef`，随提示词一起注入「画布引用范围」，并作为本轮唯一可改范围参与改动判定。原先 `AgentRef.subtree` 用来区分「只改这个节点」与「连同子级一起改」，默认 `false`，由输入框胶囊上的角标切换。

这个标记的价值只在一种场景：只想改容器本身（背景、圆角、尺寸），不碰内容。但它同时也是默认值，而绝大多数引用是「改这块」——默认把子级排除掉，等于让 Agent 看着内容却不能动。

## Goals / Non-Goals

**Goals**

- 引用即「这块区域」：节点与其全部后代都在可改范围内。
- 界面上不再出现用户无法自行推断的作用域概念。
- 范围判定、提示词、历史记录三处措辞一致。

**Non-Goals**

- 不引入替代机制（如按图层逐个勾选可编辑子级）。
- 不改变 `selectionRoots()` 的合并规则、8 个引用上限与发送后清空。
- 不迁移旧会话数据：`subtree` 字段直接忽略。

## Decisions

### D1：删掉开关，而不是把它默认打开

保留开关、只把默认值改成 `true` 也能解决 90% 的问题，但会留下一个「只有 11px 角标、点击后提示词语义整体改变」的隐藏模式。用户明确反馈这套设计无法理解，因此整体删除：`AgentRef` 不再有 `subtree`，`describe()` 不再输出「仅自身 / 含子级」，提示词规则简化为一句「只修改上面列出的节点及其子级」。

代价是失去「只改容器本身」的能力。这个能力可以用更小的引用替代（引用那个具体子节点），不需要一个全局模式。

### D2：范围判定按祖先链，而不是按标记

`classifyChanges()` 原先把「后代改动」只在 `ref.subtree` 为真时算进范围。删除标记后，规则变成：`change.designId === ref.designId` 或 `change.ancestors` 包含 `ref.designId`。这与引用语义一致，也让「本轮修改」列表自然包含子级改动。

### D3：旧的 `subtree` 字段忽略而非报错

`normalizeRef()` 只读取 `pageId / designId / kind / name`。旧会话里带的 `subtree` 被丢弃，加载不受影响；历史轮次的引用只显示名称——这正是删除概念后应有的呈现，不做兼容显示。

## Risks

- 引用一个大画框等于把整页放进可改范围，Agent 越界改动的空间变大。缓解：范围外改动仍只提示不拦截，并可用 ⌘/Ctrl+Z 撤销整轮；提示词仍要求「未列出的节点一律不可修改」。
- `elementContext()` 的 8000 字符上限与 90 行源码片段上限不变，大子树仍靠截断兜底。
