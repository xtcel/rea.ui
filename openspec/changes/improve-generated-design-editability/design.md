## Context

布局容器、组件目录和实例已经可用，但生成入口存在相反指令。CLI init 默认 v2，没有组件目录管理命令。SVG 导入有圆弧归一化实现，结构化 PathData 与 VectorTools 仅处理一个轮廓。

## Goals / Non-Goals

**Goals:** 生成结果具有可选择的业务层级、重复结构可复用、常见 SVG 可逐点编辑；提供与格式校验分开的可定位审计。

**Non-Goals:** 不自动改写任意设计，不重做外部 AquaRDM 文件，不新增布尔运算，不发布版本。

## Decisions

1. 以共同的可编辑性规则更新所有生成入口：布局先分区、局部坐标、真实业务名称、重复两次先评估组件。图层数作为软预算，禁止跨记录合并文字或跨图标合并路径。无需组件的简单页面仍为 v2。
2. 增加 `init --components` 与 `components init <dir>`：使用合法空目录，自动升级 v2→v3，v4 保留；先验证候选文件集，再写入，失败回滚；重复调用不覆盖已有组件。相比默认升级所有文档，这保留简单文档兼容性。
3. PathData 保留 `anchors/closed` 表示首轮廓，增加可选 `contours` 表示后续轮廓；全路径锚点身份唯一，累计最多 20000。旧单轮廓数据无需迁移。共用独立 SVG 路径模块，避免 svg/vector 循环依赖；圆弧按明确的 0.01 SVG 用户单位误差界细分为三次贝塞尔。
4. VectorTools 选择轮廓后编辑该轮廓，预览/提交始终重组整个 PathData；不分拆矢量图层，className 中的 `[fill-rule:evenodd]` 等样式保留。转换节点时同时保留 bindings、锁定、箭头等元数据。导入、渲染、导出共用 pathData 序列化。
5. `audit` 使用源节点树（避免实例展开产生重复误报），报告稳定 code、severity、path、node、message、hint。命名、容器直接子节点规模、结构指纹（忽略文案/位置）、轮廓边界间距和 expandPath 可转换性作为启发式；默认警告退出 0，`--strict` 有警告退出 1，格式错误退出 1。它不改变 validate/pack 既有语义。

## Risks / Trade-offs

- 启发式会误报/漏报 → 文案明确“疑似/建议”，不自动改源，不作为默认打包失败条件。
- 新 contours 无法由旧编辑器识别 → 文档与示例明确需要新编辑器；旧 d/单轮廓仍可读取。
- 误差界细分增加锚点 → 总量上限及有限值校验；曲线测试覆盖大半径、旋转、相对坐标与退化圆弧。
- 多文件落盘无法提供跨进程事务 → 候选先验证、临时文件写入、失败恢复原始字节，不覆盖已有组件。
- 组件抽象需要判断 → 两次出现触发评估，不强制所有简单图形都成为组件；审计只提示有内容的复合结构。

## Migration Plan

先更新源代码与规范，再运行单元测试、类型检查和构建，最后重建插件内 CLI/MCP 分发与可编辑示例。无需自动迁移旧文档；旧 d 在进入路径编辑时按需转换。回滚代码后，新增复合 path 可导出 d 供旧版本读取。

## Open Questions

无阻塞问题。审计阈值作为文档化启发式，后续可依据真实设计稿反馈调整。
