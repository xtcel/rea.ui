## Why

生成的设计稿虽然通过格式校验，却可能将整页图层平铺、跨业务元素合并文本与路径，缺少可复用组件，导致用户难以选择和修改。生成规范与编辑器能力脱节：组件被默认禁用，圆弧和多轮廓 SVG 无法进入锚点编辑。

## What Changes

- 统一内置 Agent、Codex 与 WorkBuddy 规范：按语义布局分组、使用局部坐标和有意义名称；优先复用已有组件，评估重复两次及以上的结构；禁止为满足图层预算跨元素合并。
- CLI 增加组件目录初始化/添加入口，自动选择 v3，保留已有 v4，不要求 Agent 手改清单。
- 扩展结构化路径以支持多个轮廓；复用 SVG 圆弧转换，明确近似误差；编辑和导出保持整体填充规则与孔洞。
- 增加独立的 `reaui audit` 可编辑性检查，输出节点定位与建议，检查平铺层级、命名、疑似重复结构、疑似跨区域路径和无法转换的路径。
- 增加可编辑的分组、组件和复合图标示例与回归验证。

## Capabilities

### New Capabilities

- `generated-design-editability`: 生成规范、组件 CLI 工作流、可编辑性审计与交付示例。
- `compound-path-editing`: 多轮廓结构化路径、圆弧近似、逐轮廓编辑及镂空往返。

### Modified Capabilities

无；当前 openspec/specs 尚无归档规范，本变更以新增能力记录契约，并衔接现有活动变更。

## Impact

涉及 `packages/design`、`packages/editor`、`packages/reaui-cli`、MCP 协议、两套插件文档、示例和分发构建。旧单轮廓 path、原始 d、v2/v3/v4 文档继续可读；新增复合 path 需要更新后的编辑器。

## 范围说明

本次修改 Rea.UI 项目及其可分发规范，不发布 npm/插件版本，不覆盖外部项目的 AquaRDM 原稿。审计是启发式建议，不证明视觉还原度，也不自动重写设计。没有布尔运算、分支矢量网络或自动从任意业务代码抽取组件。
