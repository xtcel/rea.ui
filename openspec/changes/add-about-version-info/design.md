## 决策

1. **版本口径是「配套版本」而不是「本机版本」**：关于页回答的是「这份构建产物配套哪个 CLI」，不是「用户机器上装了哪个 CLI」。因此不需要执行外部命令，浏览器版与桌面版都能显示同一口径；也不需要新增 Rust 侧 Agent 方法。
2. **单一数据源**：`apps/web/vite.config.ts` 在构建时读两个 `package.json`，用 `define` 注入全局常量。桌面版复用同一份 Vite 产物，口径自动一致。未走该构建配置的环境（Vitest）用 `typeof` 兜底为 `—`，不抛错也不伪造版本。
3. **只读路径**：`getMeta('lastOpenedId')` + `getDocument()`，刻意不用 `openDocument()`——后者会 `setMeta('lastOpenedId', id)`，让「看一眼关于页」变成一次写操作。设置窗口与主窗口同源，共享 IndexedDB，因此不需要跨窗口消息或后端接口。
4. **降级优先**：清单损坏只省略版本；快照存在但 `parseSystem()` 校验失败显示「快照无效」，没有快照显示「未固定」，两者不混淆；存储不可用或无文档时设置页仍可正常打开。
5. **hash 展示**：完整 SHA-256 在窄栏里会破坏排版，界面取前 12 位并放到 `title`，核对时既能一眼比对也能看到全值。

## 风险与取舍

- `packages/reaui-cli/src/cli.ts` 的 `VERSION` 常量仍与 `packages/reaui-cli/package.json` 各自维护，目前同为 `0.1.3`。若发版只改其一，`reaui --version` 会与关于页的配套版本不一致；本期不引入构建期一致性检查。
- `AutoSaver` 有落盘延迟，独立设置窗口读到的是已落盘版本。用「每次进入关于页重新读取」缩小这个窗口，但不做实时订阅，避免为一个只读页面引入跨窗口同步机制。
- 全局 `define` 常量只存在于该 Vite 构建产物中；把 `@rea/editor` 直接嵌入别的构建器时会显示 `—`，需要构建器提供同名 `define`。
- 关于页的版本信息来自「最近打开的文档」。从首页进入设置时，用户看到的不是某一篇指定文档，本期不额外显示文档名。
