## Context

首页当前仅存储配色和目录名称。编辑器要求静态 `@rea/design` TSX，不能执行项目 React 组件。桌面端为 Tauri，开发端为 Vite。

## Goals / Non-Goals

完整支持本地 Codex UI 生成、项目参考和可配置设计系统。首版不自动写回代码，不运行任意生成代码。

## Decisions

- 独立 Rust `rea-local-agent` 运行库复用在 Tauri 与 Vite 开发桥接，避免双份进程实现。桥接通过 stdio JSON 请求，Vite 仅在回环地址且同源时开放接口。
- Codex 使用 `exec --json --sandbox read-only --output-schema`，prompt 通过 stdin，复用本机登录与默认模型，输出在独立临时目录。后台任务可查询状态、取消，设置超时并清理临时文件。
- 项目关联存真实绝对路径；受限扫描提取文档、令牌、样式与组件作为参考，跳过隐藏目录、依赖、构建与符号链接。Codex 在项目目录只读运行。
- `.reaui` 参考通过现有 ZIP 校验解码，提取页面源，生成新文档避免覆盖原设计。设计系统与用户选择保存在本地。
- 设计系统包含语义配色、字体、字号、间距、圆角、组件规范和使用指南，提供基础/组件/指南分区预览、草稿/可用状态。AI 生成后可配置再使用。
- 生成结果必须经过 `DocumentSession` 全量校验，成功后才保存并打开。错误保留需求和上下文供重试，不制造空项目。

## Risks / Trade-offs

- CLI 登录或网络失败 → 明确展示检测结果、日志摘要与重试入口。
- 模型输出不符合静态子集 → 输出约束、前端校验，不执行代码。
- 大型项目上下文过大 → 限制扫描文件数、单文件和总字符数，显示参考文件摘要。
- 打包桌面缺少 shell PATH → 从常见安装目录发现 Codex，并允许配置绝对路径。
- Web 正式静态部署没有本地桥接 → 说明需使用桌面端或本地开发模式。

## Migration Plan

兼容原设计系统配色，补齐默认令牌；旧占位模型回退到 Codex 默认。现有文档无需迁移。

## Open Questions

用户已确认关联本地代码仅作为生成参考；首版没有待确认问题。后续如增加写回，需要单独定义代码导出与冲突处理。
