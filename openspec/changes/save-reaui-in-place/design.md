## 背景

`.reaui` 是一个 ZIP：`rea.json` + `pages/*.page.tsx` + `assets/*`。编辑器把整份文档放在 IndexedDB 里工作，磁盘文件只在「打开」与「导出」两个方向出现。`⌘S` 缺失不是快捷键没注册，而是整条「写回」链路不存在：`OpenedFile` 只序列化 `name` / `bytes` / `error`，路径在 Rust 侧被丢弃。

## 目标

1. `⌘S` 与用户直觉一致：打开了哪个文件就更新哪个文件。
2. 写回失败不能损坏原文件，也不能假装成功。
3. 不给网页层新增「写任意路径」的能力。

## 决策

### D1：路径由原生侧持有，网页层只是转述

`DocumentPaths` 保存两样东西：`bound`（文档 id → 最近一次打开或另存为的路径）与 `opened`（系统打开事件给出过的路径集合）。`save_document` 只在 `path` 命中「本文档绑定的路径」或「打开过的路径」时才跳过对话框；其余情况一律弹原生保存对话框。这样即使网页层被注入脚本，能写的也只有用户本来就用这门应用打开过的 `.reaui`。

代价：换机器或删除 `document-paths.json` 后首次 `⌘S` 会退化成「另存为」，属可接受降级。

### D2：原子替换而不是就地截断

`File::create(target)` 一旦失败或断电，原文档就没了。改为同目录写入 `.{name}.{pid}.tmp` → `sync_all()` → `rename()`：同一文件系统内 `rename` 是原子的，失败时临时文件被删除、原文件完好。没有采用「写到临时目录再复制回来」，跨文件系统会失去原子性。

### D3：状态与提示分工

顶栏的保存状态继续只反映 IndexedDB 自动保存（`保存中 / 已保存 / 保存失败 / 版本冲突`）。文件写入是用户显式动作，成功用 2.4 秒自动消失的提示回执（`已保存到「X.reaui」` / `已下载「X.reaui」`）；失败走既有 `run()` 的错误提示，仍然保留「导出 .reaui」兜底。不把文件写入塞进 `saveStatus`，避免自动保存与手动保存互相覆盖状态。

### D4：另存为改写绑定

`⇧⌘S` /「另存为 .reaui…」写入新路径后，把 `bound[docId]` 更新为新路径，之后的 `⌘S` 跟着走。原文件保持用户按下另存为前的版本——这是「另存为」的既有语义，不做隐式同步。

### D5：浏览器版退化为下载

浏览器没有路径概念，`⌘S` 触发 `.reaui` 下载并 `preventDefault()`，不再让浏览器弹「保存网页」。这也是 Web demo 里唯一合理的「保存到文件」。

## 风险与取舍

- **同一路径重复打开仍会新建副本**：`decodeReaui` 每次生成新文档 id，因此文件里的 `rea.json.id` 会在每次「打开 → ⌘S」后变化。相机等按文档 id 记录的状态可能丢；文档库会出现同名副本。本变更不处理，避免把去重、合并策略塞进一次修复。
- **只读位置**：从只读卷（如 DMG 内）打开的 `.reaui` 会写失败并报错，需要另存为。没有做「先探测可写再决定是否弹框」的预判，因为 `rename` 前无法可靠判断目录权限。
- **`⌘S` 与输入法 / 文本编辑**：焦点在输入框或正在编辑文字时沿用既有 `blocked()` 判定，不触发保存。与其它快捷键一致。
- **大于 256MB 的文档**：字节仍以 JSON 数组跨 IPC（与打开路径一致），超大文档会有序列化开销；既有打开路径已是同一量级，本次不引入新的 IPC 方案。
