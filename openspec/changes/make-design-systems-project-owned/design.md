## Context

系统库草稿在 localStorage，发布版本在 IndexedDB meta，项目固定快照在文件映射。页面生成提示词包含快照，但可编辑文件不包含快照，返回文件在补回快照前就被完整文档校验；v4 又被组件目录的 `version === 3` 判断拒绝。创建流程隐式发布并吞掉部分绑定错误，现有项目无系统时回退到全局选择。

## Goals / Non-Goals

**Goals:** 项目系统自包含、相互隔离；采用不隐式发布；渲染/AI/校验一致；项目内人工与 AI 编辑可撤销；独立资产库可持久化和迁移；CLI/MCP 遵循同一契约。

**Non-Goals:** 见 proposal 范围说明；不改造系统规范成可执行 React 组件，不重写历史快照，不更换页面视觉风格。

## Decisions

### D1：文件快照是项目权威数据

沿用 `design/system.json` 与文档 v4。从库采用时复制合法快照，无需先发布；新建先构造包含系统的完整 DocumentRecord，再首次写入数据库。全局 default 只参与新建，不传入已有项目 Agent 的系统选择逻辑。未绑定项目传递 null，提示词诚实描述无系统。

### D2：编辑文件与验证上下文分开

AI 工作区仍只允许清单、页面、组件文件写入，不把系统设置为可写。新增共享候选构造逻辑：合并宿主快照、保留 v4、校验身份和完整文档，再提取可编辑文件。CLI/API 的返回校验与最终提交使用该逻辑。API 提示词通过宿主完整文件读取页面，不能对剥离快照的文件再次独立解析。

### D3：v4 是累积文档能力

组件目录允许 v3 及以上；新增组件不降低 v4。同步修正提示词和工具，保留 v2/v3 文件兼容。

### D4：项目编辑复用系统工作台

复用 DesignSystemPage 的令牌、规范和 AI 编辑，增加项目作用域：保存使用文档 system 事务，项目快照首次修改时建立项目系统 id 并记录 origin（来源 id/revision/hash）。继续编辑保留 origin；库版本不会被隐式覆盖。项目可新建系统、采用库版本、查看完整系统，并显式另存为独立系统。项目编辑 AI 使用独立的文档元数据会话文件，随 .reaui 保存，排除在页面 AI 参考之外。非法草稿可留在当前编辑页面，但不能覆盖最后有效项目快照；关闭时明确报告未保存问题。

### D5：共享草稿类型和统一库仓储

可编辑草稿和已校验的不可变包各有明确类型，在 design-system 包声明。系统库草稿通过 storage API 存入 IndexedDB meta，编辑器不再直接写 localStorage。首次读取复制旧数组，保留旧来源用于回滚；迁移幂等，不覆盖已经存在的库。发布版本沿用现有注册表，采用系统不增加发布版本。旧 `published` 字段仅兼容“启用”含义，revision/hash 才表示已发布身份。

### D6：外部接口采用同一文档事务

CLI 增加 `system` 读取/设置/移除命令，设置校验包、通过 DocumentSession 事务验证所有引用后再写入。MCP 增加系统读写工具以及创建时可选 system 参数；现有接口不传参数时行为兼容。非法包或引用冲突不得改动原项目。独立系统支持导出包 JSON，DESIGN.md 继续作为可读参考和 AI 提取资料。

## Risks / Trade-offs

- 项目删除令牌可能破坏页面 → system 事务以完整文档检查并拒绝，保留最后有效快照。
- 异步系统库保存与切换竞争 → 仓储原子 updateMeta；保存/关闭等待已排队的写入，错误留在界面。
- 旧系统数据不完整 → 迁移保留草稿形状；采用/发布时才要求合法包，不静默补齐 AI 结果。
- 项目自定义快照不再等同库版本 → 显示项目作用域并保存 origin；只有显式采用才更新。
- 不可回滚跨版本文件能力 → v4 文件保持既有格式，旧 v1 系统字节不自动改写；回滚应用前可导出文件和保留的旧 localStorage。

## Migration Plan

按 tasks 的四阶段实施并各自验证。旧项目继续读取，未绑定项目不自动绑定任何系统；旧全局选择迁移为新建默认值；系统库首次访问时迁移。最后执行全量 TypeScript/Vitest、Rust、本地构建与浏览器验收，并更新架构/协议说明。
