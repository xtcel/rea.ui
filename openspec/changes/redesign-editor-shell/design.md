## Context

现有界面见 `packages/editor/src/EditorApp.tsx`：`app-header`（品牌 + 视图切换 + 导出）、`workspace-toolbar`、左侧 `LayersPanel`（页面列表 + 图层树）、右侧 `Inspector`、底部状态栏；画布 `Canvas.tsx` 按 viewport 并排渲染同一个 Page。M1 之后，一个 Page 就是一块含多个画框的无限画布。

## Goals / Non-Goals

**Goals**
- 用户不需要知道「源码」的存在也能完成全部设计工作。
- 布局与交互参考 Figma / Sketch 的成熟模式，降低学习成本。
- 编辑器界面与设计画布样式严格隔离。

**Non-Goals**
- 多选、框选、吸附、编组、拖拽改父级（M3）。
- 属性面板的细化字段（M4；本阶段「设计」标签先沿用现有字段，放入新的分区外壳）。
- 暗色主题、可自定义快捷键、多语言切换。
- 协作光标、评论。

## Decisions

### D1. 布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ ☰  │ 移动 画框 形状▾ 文字 抓手 │ ↶ ↷ │  文档名 / 页面名 · 已保存  │ 100%▾ │
├───────────────┬───────────────────────────────────┬──────────────────┤
│ 页面       +  │                                   │ 设计 │ 检查      │
│  首页 ✓       │   Desktop          Mobile         │ ──────────────── │
│  设置         │  ┌───────────┐    ┌─────┐         │ （属性分区）      │
│ ────────────  │  │           │    │     │         │                  │
│ 图层          │  └───────────┘    └─────┘         │                  │
│ ▾ # Desktop   │                                   │                  │
│     T 标题    │                       [- 100% +]  │                  │
└───────────────┴───────────────────────────────────┴──────────────────┘
```

- 顶栏高 44px：左侧是主菜单与工具组，中间是文档 / 页面名称和保存状态，右侧是缩放下拉。
- 左栏宽 240px，右栏宽 280px，两栏宽度可拖动调整（范围 200–400px），宽度保存在 localStorage。
- 页面面板与图层面板之间有可拖动的分隔条，页面面板可以折叠。
- 没有状态栏。保存状态以文字图标形式放在顶栏。

### D2. 「检查」标签代替源码视图

- 选中节点时，显示该节点的 TSX 片段（含子节点，超过 200 行时截断并提示）。
- 没有选中时，显示当前页面的概要（页面名、画框数量、图层总数）。
- 只读，带「复制代码」按钮。不提供下载整个文件的入口，整页代码导出放在主菜单。
- 通过 `@rea/document` 提供的节点源码范围取得片段，不另存副本。

### D3. 工具栏

| 位置 | 内容 |
|---|---|
| 工具组 | 移动 V、画框 F、形状（矩形 R / 椭圆 O，下拉记住最后选择）、文字 T、抓手 H |
| 历史 | 撤销、重做 |
| 视图 | 缩放百分比下拉：放大 / 缩小 / 缩放到 100% / 适应全部 / 适应选中 |

- 把原来的「删除」按钮去掉（Delete 键即可，Figma 也没有这个按钮）；「适应画布」并入缩放下拉。

### D4. 主菜单（☰）

文档：新建文档、打开文档…、重命名、导入 `.reaui`…、导出为 `.reaui`；页面：导出当前页面代码（.tsx）；其他：快捷键一览。「打开文档…」打开 M1 提供的文档列表对话框，本阶段把它做得更完整（缩略图不做，列表显示名称与更新时间）。

### D5. 编辑器界面使用 Tailwind，与设计画布隔离

- 编辑器界面在构建期用 `@tailwindcss/vite` 处理；设计画布在 Shadow DOM 中使用运行时编译出的 CSS（见 M1 D4），两者互不影响。
- 在 `packages/editor/src/ui/` 下建一个小型控件库：`Button`、`IconButton`、`Tooltip`、`Menu`、`Tabs`、`Panel`、`Section`、`Field`、`Dialog`、`SplitPane`。M4 的属性控件会基于它们。
- 旧的 `styles.css` 按组件逐个迁移，迁移完成后删除。
- 颜色与间距用一组 CSS 变量作为编辑器主题，便于以后做暗色模式。

### D6. 无限画布

- 页面画布上，每个顶层 Frame 都是一个画框，位置与尺寸取自 className（M1 D3）。
- 画框的标题固定显示在画框左上角外侧（字号不随缩放变化，缩放过小时隐藏），点击标题选中画框；选中画框后标题高亮。
- 页面上的游离图层直接显示在画布上，没有画框标题。
- 相机、缩放范围（0.1–3）、平移与快捷键沿用现有行为，新增 `Shift+1`（适应全部）、`Shift+2`（适应选中）、`Shift+0`（100%）。
- 新建页面后自动适应；切换页面时恢复该页面上次的相机位置（会话内保存）。
- 空页面显示空状态提示：「按 F 创建画框」。

### D7. 本阶段对现有编辑能力的处理

选择、拖动、缩放、绘制（画框 / 矩形 / 椭圆 / 文字）沿用现有逻辑，只适配新模型。新建矩形、椭圆、文字时：点在画框内则成为该画框内的子图层；点在空白处则成为页面游离图层。更复杂的容器命中（嵌套 Frame、Group）留给 M3。

## Risks / Trade-offs

- **布局重做会让已有交互回归**：把拖动 / 缩放的数学逻辑从 `Canvas.tsx` 中拆成纯函数并写测试，再迁移界面。
- **Tailwind 迁移工作量**：按组件逐个迁移，允许新旧样式在迁移期并存，通过类名前缀避免冲突（旧样式前缀 `rea-`）。
- **隐藏源码后调试变难**：开发者仍可在「检查」标签里查看代码；主菜单的导出也保留。
