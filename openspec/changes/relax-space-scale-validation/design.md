## Context

`spaceIssues()` 对 `space.scale` 原本要求「非空、≤ 16 项、正整数、严格升序不重复」。第一轮只删掉了项数上限；第二轮用户的真实系统（AquaRDM）刻度是 `0 / 2 / 3 / … / 30`，开头的 `0` 触发「间距刻度必须是正整数」，发布与「用于 UI 生成」再次被禁用。

刻度只服务一件事：派生 `--rea-ds-space-<value>` 变量。校验应该只守住「能变成合法 CSS 变量」这条线：

- `0` → `--rea-ds-space-0: 0px`，合法，而且是最常用的贴边间距；
- 乱序 → 变量集合完全相同，只是注入顺序不同；
- 小数 → 变量名 `--rea-ds-space-8.5` 非法（ident 里不能有点）；
- 负数 → 作为间距没有意义，`padding: -4px` 也不合法；
- 重复 → 同一个变量名声明两次，`validateTokens()` 的冲突检查还会给出「space.8 与 space.8 派生出同名变量」这种看不懂的文案。

## Goals / Non-Goals

**Goals**

- 含 `0`、档位多、顺序随便的刻度都能通过校验并发布。
- 校验只剩真正会导致变量不可用或撞名的规则。
- 报错文案直接说人话：至少 1 项 / 0 或正整数 / 不能重复。

**Non-Goals**

- 不排序、不去重、不截断模型返回的刻度。
- 不调整 `space.unit`、`typography.roles`、`motion` 等其它分组的取值范围。
- 不改生成 schema 与发布闸门的其它规则。

## Decisions

### D1：允许 0

`0` 是最常见的间距（无间隙、贴边），Tailwind 也把它作为第一档。`--rea-ds-space-0:0px` 是合法声明，没有任何下游会因此出错。

### D2：去掉升序要求

顺序没有语义：`systemVariables()` 按数组顺序输出变量，`conformance()` 用 `includes()` 查表，DESIGN.md 导出会按对象键重新排列。既然排序不影响结果，就不该因为「模型没按大小排」阻断发布。

### D3：重复仍然报错，但只报一次

重复值会派生出同名变量。`validateTokens()` 在有任何 issue 时会提前返回，因此在这里给出「间距刻度不能重复。」就能盖住后面那条冲突提示，用户看到的是能直接改的说明。

### D4：`spacing.unit` 的兜底不再取 `0`

`importDesignMarkdown()` 原本用 `scale[0]` 当基数兜底；允许 `0` 之后，缺少 `unit` 的设计文档会被兜底成 `unit: 0`，再被「间距基数必须是 1–64 的整数」拦住。改为取最小非零刻度，仍缺时退回默认值。

## Risks / Trade-offs

- **重复的刻度**：仍然阻断发布。若后续认为重复也该容忍，需要同时处理变量名冲突检查，否则只会把错误换成一句更难懂的话。
- **超长刻度**：设计系统页把刻度排成一排 `<code>`，几十档会换行；真实模型输出受 token 预算限制，暂不做折叠。
- **既有草稿**：之前为了避免报错手工删掉的刻度不会被恢复，重新生成即可。

## Open Questions
